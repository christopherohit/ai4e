## Phase D — Viz build pipeline

Recipe per repo goes in `blog/scripts/viz-recipes.mjs` (object keyed by slug: `{ src, slug, install, build, out, env, patches }`). `scripts/build-viz.mjs [slug...]`: rsync `../<src>/` → `.viz-build/<slug>/` (exclude .git, node_modules), apply patches (`viz-patches/<slug>/*.patch` via `git apply --directory` or JS string replacements in the recipe), run install+build with env, copy `out` → `public/viz/<slug>/`, write `public/viz/manifest.json` `{slug: {ok, builtAt, error?}}`. Never touch the original repo dirs.

Each viz task is done when: `public/viz/<slug>/index.html` exists, served from `/viz/<slug>/` (via `npx astro preview` or `python3 -m http.server` at blog/dist or public root) the app loads with no 404s for its own assets (check with Playwright: collect failed requests + console errors) and renders its main view. Document anything that doesn't work (e.g. backend-only features) in the recipe notes.
